## Build
On a Mac with Xcode 26+: install XcodeGen, run `xcodegen generate`, then open CardLedger.xcodeproj. App targets iOS 26 for Foundation Models. Current recognition consumes OCR from both cropped faces; direct multimodal image understanding is not implemented.

Run `python3 -m unittest discover -s tests -v` for worker tests. iOS StoreTests cover persistence, import conflicts and corruption protection; these run on the GitHub macOS runner, not this Linux host. Tests also cover crop geometry, exact decimal values, checksum corruption and legacy photo migration.

## Private worker
Use an isolated trusted host/account with Codex CLI and your authenticated Codex session. Keep that authentication out of source control and off the iPhone. Install `worker/requirements.txt`. Set a random CARD_WORKER_TOKEN of at least 32 characters and run `python3 worker/worker.py`. It listens only on 127.0.0.1:8787. Put it behind a TLS reverse proxy/private network; do not expose the Python HTTP server directly. Configure the HTTPS endpoint and device token in app Settings.

The worker serializes requests, caps attempts at 30/day by default, caches seven days, validates identities and JSON, and computes only item-only USD sold comps. No cloud photo upload is performed. Set CARD_WORKER_DB to a private protected path; its cache contains query results. Review source-specific data retention terms before enabling ongoing storage. The worker is a prototype, not a hardened public service. A local integration attempt on 2026-11-14 could not initialize the Codex app-server because this Work runtime mounts its state filesystem read-only; ephemeral mode also failed. No successful live pricing lookup is claimed. Codex read-only sandbox and prompt restrictions do not replace process/container isolation or website evidence validation.

## Scan flow
Tap **+** to open “Scan front of card” immediately. The camera continuously detects four corners, checks card-like proportions, waits for focus/exposure and a stable 0.8-second hold, then captures automatically. No shutter or confirmation button is required. After the front is captured, a two-second full-screen confirmation shows a green checkmark, the cropped front thumbnail and a turn-over instruction, with a success haptic and VoiceOver announcement. Detection continues behind the confirmation so a quick edge-on flip is remembered. The back screen keeps a front-captured badge and thumbnail. A brief loss of the card during the flip prevents immediately capturing the unchanged front twice; the UI explicitly prompts for a flip or brief removal if still waiting. Capture is disabled throughout the confirmation, and a fresh stable hold is required for the back. Backgrounding and the photo picker preserve an already-completed flip.

The rectangle request returns all candidates and combines them with a physical-edge fallback. At a maximum 512-pixel analysis dimension, the fallback suppresses texture, accumulates line votes along image-gradient directions and requires sustained edge support on all four sides of a plausible card. It prefers the largest supported outline, resolving similar-area proposals by line strength. This recovers outer edges even when Vision only proposes printed statistics boxes. Live scanning, Photos import and legacy crop recovery share this selection. A detected clipped outer card is rejected instead of selecting an inner rectangle. Contrast, glare, blur and occlusion still require device evaluation. The two supplied Volpe back photos are test-only fixtures, with independently marked physical corners; regressions exercise imports and camera-format pixel buffers. Export validation rejects an IPA containing either sample photo.

The camera prefers the triple or dual-wide virtual camera, with a wide-camera fallback. On supported devices, iOS can automatically switch to a macro-capable lens. Continuous autofocus and exposure target the detected card center, update when it moves, and respond to subject-area changes; capture waits for focus/exposure to settle. Visible focus guidance and a hold-progress ring make the camera state explicit. Hardware focus and macro behavior require physical-device evaluation.

Both detected rectangles are perspective-corrected. Each face is independently evaluated at 0°, 90°, 180° and 270° using Vision OCR confidence and reading-direction evidence. A clear winner rotates the corrected image and its saved crop coordinates; sparse or ambiguous evidence leaves the image unchanged and flags that face for optional rotation in edits. This heuristic uses Latin-script text evidence, including diacritics; textless artwork and unsupported writing directions are not guessed. Landscape faces retain their own aspect ratio. OCR runs on both sides concurrently, then on-device Apple Intelligence extracts a candidate identity from the combined text. Cropped front/back textures rotate in 3D with a presentation-only Metal holographic shine. Player/team animate into view when identification finishes, while the optional private Codex worker researches the candidate. A price spinner appears only if research is still pending three seconds after the timed identity reveal. Once recognition and pricing have resolved, Continue replaces the loading indicator. The card keeps rotating until Continue is tapped; only then does the presentation shrink into a row and insert into the collection. Unavailable identity/pricing results still allow Continue with a review note. Pricing failures save the scan with an unavailable/review state rather than inventing a value. Tap an existing row to reopen its two-sided rotating holographic presentation with saved identity and value. The ellipsis menu provides Edit and Remove. Saving edits returns to the viewer with current store values and photos; viewing does not rerun recognition or research. Remove asks for confirmation, keeps the viewer open on failure, and dismisses to the collection only after successful deletion. Reduce Motion remains respected by the shared card renderer.

The scanning overlay combines a custom vector baseball-player bust and shoulder bat with a dashed, subtly rounded 2.5:3.5 card outline. UIKit blur and vibrancy are masked to the vector strokes so the camera view remains sharp. A dark contrast stroke, Increase Contrast support and a Reduce Transparency fallback keep the guide legible.

Exact duplicate detection compares normalized player, sport, year, manufacturer, set, card number, explicit variant and grade, plus certificate when present. Conflicting nonempty teams also prevent a match. Missing or unknown required fields do not establish an exact match, and images alone are not treated as proof of matching editions. A match notice appears in the completed spinning view. Continue opens Add duplicate / Overwrite existing / Discard scan choices. Multiple matches require explicitly selecting a copy before overwrite. Adding saves a new UUID; overwriting keeps the selected UUID, original added date, status, notes, tags, location, purchase/disposition history and manual valuation while replacing scan-derived fields. The match is revalidated at commit, and failed saves offer a return to the review choices. Discard never mutates the collection.

Photo-library fallback follows the same front/back sequence and requires a complete detected rectangle. Cancellation stops later insertion. Original evidence is preserved separately from corrected display copies. Reduce Motion disables continuous rotation and shader animation.

- Check both faces in the rotating reveal and player/team motion. After processing resolves, verify Continue appears and the viewer stays open until tapped. - Review OCR and identity, confirm only exact cards, and verify uncertain parallels remain manual.
